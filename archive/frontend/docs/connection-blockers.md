# Mobile connection blockers — Batch L

Every item below is blocked on work owned by another agent, or on an owner decision.
Nothing has been worked around, guessed at, or stubbed.

Status vocabulary: **BLOCKED** = cannot proceed without the named dependency.

---

## LB-01 — QR payload contract does not exist

**BLOCKED — KiloCode**

The mobile scan needs a real app/PWA permission the frontend does not have, and the School Dashboard states `QR secure backend se generate hoga` — the QR is generated by the secure backend. No QR payload shape, expiry or signature contract exists (the same absence recorded as Batch C's C-O-03). `assertConnectionFlowMatchesReferences()` keeps the transcribed copy (`Camera scan ke liye real app/PWA permission chahiye`) so the guarantee cannot be quietly dropped.

**Unblock requires:** KiloCode publishes the QR payload contract and the generation endpoint.

---

## LB-02 — connectSchool() is a demo transition, not a session

**BLOCKED — KiloCode**

The reference reports `Connected to <name> in this demo`. `connectionReport()` therefore returns `demo: true` and never a session token. There is no connect endpoint, no connected-school response and no tenant-resolution contract.

**Unblock requires:** KiloCode publishes the connect contract, including server-side tenant resolution.

---

## LB-03 — Selected-school persistence has no approved scope

**BLOCKED — owner decision + KiloCode**

The reference writes no localStorage, sessionStorage or IndexedDB for the connection, and no storage contract exists. `assertNoUnapprovedStorage()` therefore fails the suite on any such write, and `selectedSchool()` is in-memory only. This is the L-O-04 adjacent decision: an exact storage scope must be approved before anything persists a school.

**Unblock requires:** the owner approves an exact storage scope, then KiloCode publishes the persistence contract.

---

## LB-04 — Mobile UI regression cannot be run

**BLOCKED — Cline**

L-O-06 requires testing the QR/manual/login/role/error/logout flow at phone widths. That needs Cline's UI-lock harness and the merged real app. The reference is a self-contained demo, so the flow can only be verified against the reference copy, not on a real device.

**Unblock requires:** Cline's harness approval and the owner's review/merge of Batches A–L.
